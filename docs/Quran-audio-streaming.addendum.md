## 1. الغرض والحدود

إضافة مشغل اختياري لتلاوة آيات القرآن المرتبطة بخطوة التعلّم في جزء عمّ. يشغّل المتصفح ملف الآية مباشرة من EveryAyah عبر HTTPS. تبقى قراءة النص والتعلّم الحاليان صالحين عند غياب الشبكة أو الصوت أو تعذّر تشغيله.

النطاق هو القرآن فقط: جزء عمّ، السور 78–114، وعددها 564 آية وفق Implementation-contract §2.1 (D68). المقترح التقني الأولي لقارئ واحد هو husary، ومجلده Husary_64kbps. لا يُعرض اختيار قارئ في البداية.

لا تشمل الميزة صوت الحديث، أو تحويل النص إلى كلام، أو توليد صوت بالنموذج، أو التسجيل بالميكروفون، أو تقييم النطق، أو تنزيل الملفات أو تخزينها دون اتصال، أو تمريرها عبر خادم التطبيق أو تحويلها، أو رفعها إلى التخزين، أو خدمة مدفوعة، أو لعبة خامسة، أو مخطط قاعدة بيانات أو نقطة API أو اعتماد برمجي جديد.

ملف الصوت الكامل للآية قد يتضمن كلمات خارج الجزء المظلل من المقطع. لذلك تعرض الواجهة أن الصوت للآية كاملة، ولا توحي بحدود صوتية دقيقة للكلمات أو الجزء. لا يُشترط الصوت لإكمال القراءة أو الجلسة ولا يؤثر غيابه في أي تقييم.

## 2. مدخلات العقد وربط الآيات

المدخل المعتمد هو PassageView في Implementation-contract.md §7: يجب أن يكون path = 'quran'، وأن تكون كل وحدة مستهدفة من units[] ذات kind = 'ayah' ومرجع reference نصيًا بصيغة ASCII معتمدة surah:ayah، مثل 78:1. هذا الحقل هو مرجع الآية.

لا يستنتج التطبيق رقم السورة أو الآية من unitRef الرقمي، أو مرجع المقطع المعروض، أو عنوان السورة، أو رابط يقدمه العميل. لا تتغير PassageView أو SourceRef أو QuestionBase أو Step أو SessionSnapshot أو أي رسالة API قائمة.

يُعدّ التسلسل من الوحدات الموثوقة وفق ترتيب المصدر داخل المقطع. خيار الخطة العكسي يغير ترتيب المقاطع فقط؛ لا يعكس ترتيب الآيات في المقطع. عند تكرار المرجع أو عدم صلاحيته أو خروجه عن جزء عمّ، يتعطل مشغل ذلك المقطع برسالة واضحة. وإذا لم تتوفر بيانات صوت لآية واحدة، يتعطل تشغيل المقطع كاملًا مع بيان السبب، ويستمر النص والتعلّم.

تُجهّز بيانات الربط مسبقًا من سجلات المصدر التي جرى التحقق منها، ولا يُستدعى MCP عند نقر المتعلم ولا تُركّب الروابط تخمينًا أثناء التشغيل. يلزم وجود سجل مطابق لكل مرجع آية قبل إتاحة المشغل لذلك المقطع.

## 3. التصميم المقترح

### 3.1 الملفات الجديدة المقترحة لاحقًا

هذه مسارات مستقبلية Planned، وليست ملفات موجودة أو تفويضًا بالبدء في التنفيذ:

| المسار المقترح | المسؤولية |
|---|---|
| backend/app/workflow/quran_audio_manifest.py | تحضير بيانات وصفية معزولة، تقرأ وحدات مصدر القرآن المكتسبة وتستعمل محوّلًا للمصدر؛ لا تعدّل النص الأصلي أو حزمة المحتوى أو سير العمل الحالي |
| frontend/src/lib/quran-audio/types.ts | أنواع داخلية خاصة بالواجهة لتعريف الفهرس والصف والحالة والنتيجة |
| frontend/src/lib/quran-audio/queue.ts | تحويل مراجع آيات PassageView إلى قائمة تشغيل مرتبة باستخدام الفهرس المتحقق منه |
| frontend/src/lib/quran-audio/manifest.generated.json | بيانات وصفية ثابتة مولدة ومراجعة؛ لا يحتوي ملف MP3 |
| frontend/src/components/quran-audio/QuranAudioPlayer.tsx | مشغل اختياري للآية كاملة، بحالات تشغيل واضحة وباتجاهي RTL وLTR |

التوقيع الداخلي المقترح للواجهة:

```ts
buildQuranAudioQueue(
  passage: PassageView,
  manifest: QuranAudioManifest
): AudioQueueResult
```

هذه أنواع خاصة بالواجهة وليست DTOs جديدة على السلك. QuranAudioManifest تصور داخلي يتضمن schemaVersion: 1، وreciterId: 'husary'، ومفتاح نسخة المصدر quran-hafs-quranenc، ووقتَي التوليد والتحقق، ومدخلات مرتبة تحتوي reference, surah, ayah, audioUrl, versePageUrl. لا يحتوي الفهرس نصًا دينيًا، أو بيانات متعلم، أو أسرارًا. مصدر أرقام الآيات هو سجل QuranEnc المكتسب والتحقق من مطابقته؛ لا تُخترع تغطية.

يُقبل audioUrl فقط إذا كان HTTPS وعلى النطاق everyayah.com، ومساره تحت /data/Husary_64kbps/ ويطابق المرجع، ولا يتضمن query أو بيانات اعتماد أو fragment. تُراجع كل تحويلة ويجب أن يبقى المضيف النهائي على HTTPS والنطاق المعتمد everyayah.com؛ تُرفض التحويلة إلى أي وجهة أخرى. يُحفظ رابط الآية المرجعي الأصلي versePageUrl من سجل المصدر لأغراض التتبع؛ ولا يحل محل النص أو استشهاد مصدر القرآن الحالي.

### 3.2 التشغيل في الواجهة

يستخدم المكوّن عنصر HTML audio الأصلي مع preload="none" وعناصر التحكم الأصلية. هذه القيمة تلميح للمتصفح وليست ضمانًا لعدم جلب الملف؛ لذلك لا يُسند src إلا بعد نقرة تشغيل صريحة من المتعلم. يحتاج التشغيل إلى اتصال إنترنت. إذا رفضت play() أو فشل التحميل، يعرض المشغل حالة خطأ مفهومة بلا إعادة محاولة تلقائية أو حلقة إعادة تشغيل. يوضح المشغل حالة كل آية، ويفصل خيار تكرار المقطع عن عناصر التحكم، ويعرض بالعربية والإنجليزية أن الصوت للآية كاملة وأن مصدر الصوت خارجي. إن استُخدمت crossOrigin="anonymous" فتكون فقط بعد التحقق من ترويسات CORS للمصدر؛ لا يُسمح بخفض الإعداد إلى طلب ذي بيانات اعتماد إذا غابت تلك الترويسات.

يبدأ الدمج في خطوة learn لآيات القرآن فقط، في سياق شاشة الجلسة S-19 وحزمة F9 بعد اعتماد G1. لا يظهر للمقاطع الحديثية، ولا في أسئلة الألعاب أو المراجعة أو الاختبار الأولي أو مرحلة ترتيب الكلمات أو الاختيار أو الاسترجاع. لا يكشف الصوت إجابة أو تلميحًا في مرحلة تقييم.

تتوقف الوسائط ويُزال src وتُمسح إحالتها عند الانتقال من المقطع أو الجلسة أو الخطة أو الحساب، أو عند الانتقال إلى أي سؤال/مراجعة/اختبار/لعبة، أو عند مغادرة التبويب أو إخفائه أو مغادرة الصفحة. يجب تجاهل أحداث play/ended والمؤقتات القديمة بعد التنظيف، حتى لا تعيد تشغيل الصوت بعد التنقل أو دخول الحساب أو مرحلة السؤال. قائمة التشغيل مؤقتة في الذاكرة؛ لا تنزيل صوت ولا تخزين صوت تديره ميزات التطبيق أو Service Worker أو IndexedDB أو outbox. قد يستخدم المتصفح تخزينًا مؤقتًا أو buffering اعتياديًا للوسائط؛ لا يعد هذا التصميم بمنعه.

لا ينتج عن callbacks الصوت حدث جلسة أو إنجاز يومي أو وقت نشاط محتسب أو إجابة أو تغطية جزء أو إتقان أو streak. سياسة احتساب النشاط الحالية هي المرجع، ولا يمنح تشغيل الوسائط رصيدًا. لا تغييرات على E20 أو SessionSnapshot أو جداول قاعدة البيانات أو أحداث التقدم.

### 3.3 فحص العقد (مراجعة المنسق، ٤ أكتوبر ٢٠٢٦، قراءة فقط)

- `PassageView.path` يساوي `'quran'` لمقاطع جزء عمّ، ووحدات القرآن من النوع `'ayah'` (يبنيها `backend/app/workflow/segmentation.py` بالنوع `"ayah"`).
- `units[].reference` لوحدة قرآنية نص ASCII بصيغة `"surah:ayah"` بلا أصفار بادئة، يبنيه `backend/app/workflow/segmentation.py` بالصيغة `f"{surah}:{record.ayah}"` (مثل `"78:1"`). في المقابل يبني `ref_str` في `backend/app/workflow/passages.py` مراجع الرموز `"unitOrdinal:tokenIndex"` (مثل `"12:3"`)، و`highlight.startRef` و`highlight.endRef` مراجع رموز أيضًا: لا يجوز أبدًا قراءة أيٍّ منهما مرجع آية. أما مرجع المقطع نفسه (مثل `"78:1-5"`) فتسمية عرض ولا يُحلَّل هو الآخر.
- بموجب D66 يتألف مقطع القرآن من آيات كاملة من سورة واحدة، فتسرد `units[]` آيات متتالية من سورة واحدة بترتيب المصحف؛ والخيار العكسي للخطة يغيّر ترتيب المقاطع وحده.
- لا يلزم تغيير في DTO أو API أو قاعدة البيانات أو الاعتماديات: تقرأ القائمة `path` و`units[].kind` و`units[].reference` فقط. لا ينشئ الصوت أبدًا حدث جلسة أو وقت نشاط أو إنجازًا يوميًا أو إجابة أو تغطية جزء أو إتقانًا أو streak أو أي رصيد آخر.

### 3.4 الأنواع الداخلية في الواجهة

الأنواع الداخلية في `frontend/src/lib/quran-audio/types.ts`؛ وهي ليست DTOs على السلك:

```ts
export interface QuranAudioManifestEntry {
  reference: string;    // "78:1": ASCII surah:ayah, no leading zeros
  surah: number;        // 78 to 114
  ayah: number;         // 1 or more
  audioUrl: string;     // https://everyayah.com/data/Husary_64kbps/078001.mp3
  versePageUrl: string; // verse page of the verified source record; traceability only
}
export interface QuranAudioManifest {
  schemaVersion: 1;
  reciterId: "husary";
  sourceVersionKey: "quran-hafs-quranenc";
  generatedAt: string;  // ISO 8601 date-time
  verifiedAt: string;   // ISO 8601 date-time
  entries: QuranAudioManifestEntry[]; // unique references, ascending by surah then ayah
}
export interface AudioQueueItem { reference: string; surah: number; ayah: number; audioUrl: string; }
export type AudioUnavailableReason =
  | "not_quran" | "empty_passage" | "invalid_reference" | "duplicate_reference"
  | "missing_audio" | "invalid_manifest";
export type AudioQueueResult =
  | { status: "ready"; items: AudioQueueItem[] }
  | { status: "unavailable"; reason: AudioUnavailableReason; reference: string | null };
```

### 3.5 قواعد الربط في `buildQuranAudioQueue(passage, manifest)`

دالة نقية ومتزامنة، بلا شبكة.

1. إذا لم يكن `path` يساوي `'quran'`، أو كان `kind` لأي وحدة غير `'ayah'`: النتيجة unavailable بالسبب `"not_quran"` (لا يُعرض المشغل إطلاقًا ولا تظهر أي رسالة).
2. إذا لم توجد وحدات: `"empty_passage"`.
3. يجب أن يطابق كل `units[].reference` النمط `^[1-9][0-9]{0,2}:[1-9][0-9]{0,2}$` برقم سورة من 78 إلى 114؛ وأن تكون كل الوحدات في سورة واحدة، وأرقام الآيات متتالية تمامًا وتصاعدية بترتيب `units[]`؛ وإلا فالنتيجة `"invalid_reference"` حاملةً أول مرجع مخالف.
4. إذا تكرر مرجع: `"duplicate_reference"`.
5. يجب أن تكون ترويسة الفهرس `schemaVersion: 1` و`reciterId: "husary"` و`sourceVersionKey: "quran-hafs-quranenc"`؛ وإلا فالنتيجة `"invalid_manifest"`.
6. يلزم لكل مرجع إدخال واحد بالضبط في الفهرس يتفق `surah` و`ayah` فيه مع المرجع. غياب آية واحدة يعطّل المقطع كله: `"missing_audio"` (لا يُشغَّل مقطع ذو تغطية جزئية جزئيًا أبدًا). وإذا وُجد إدخالان أو أكثر لمرجع واحد، أو إدخال لا يتفق `surah` أو `ayah` فيه مع مرجعه، فالنتيجة `"invalid_manifest"`؛ أما غياب الإدخال فيعطي `"missing_audio"`.
7. يجب أن يساوي `audioUrl` لكل إدخال مستعمل تمامًا `https://everyayah.com/data/Husary_64kbps/${SSS}${AAA}.mp3`، مع حشو رقمَي السورة والآية بالأصفار إلى ثلاثة أرقام. تفرض المساواة التامة: HTTPS، والمضيف everyayah.com بلا منفذ، والمسار `/data/Husary_64kbps/`، والمطابقة للمرجع، وغياب query وبيانات الاعتماد وfragment. أي إخفاق يعطي `"invalid_manifest"` للمقطع كله.
8. الجاهز: العناصر بترتيب `units[]` (ترتيب المصحف)، ولا يُعاد ترتيبها أبدًا.

يأتي الرابط دائمًا من الفهرس؛ وقاعدة المساواة التامة تتحقق منه فقط، ولا يُبنى أي رابط أثناء التشغيل. التحويلات: يتحقق مولّد الفهرس (QAUD-02) بطلبات HTTPS من أن كل ملف يستجيب دون مغادرة everyayah.com؛ وأثناء التشغيل تجعل `media-src` في Content-Security-Policy (§3.8) المتصفح يرفض تحويلة وسائط إلى أي مضيف آخر.

### 3.7 التنظيف

- روتين تحرير واحد: `pause()`، ثم `removeAttribute('src')`، ثم `load()` لتحرير المورد، ثم مسح موضع القائمة والحالة، وزيادة عدّاد الجيل (generation counter).
- يفحص كل معالج حدث (`play` و`playing` و`pause` و`ended` و`error` و`waiting`) وكل وعد `play()` معلّق عدّاد الجيل وعلم التخلص (disposed flag) أولًا، فلا تعيد الأحداث القديمة ولا الوعود القديمة تشغيل الصوت أبدًا.
- يجري التحرير عند إزالة المكوّن (مغادرة خطوة التعلم إلى أي سؤال أو مراجعة أو اختبار أو لعبة؛ أو الانتقال إلى مقطع أو جلسة أو خطة أو حساب آخر؛ أو تسجيل الخروج؛ أو أي تغيير في المسار)، وعند `visibilitychange` إلى `hidden`، وعند `pagehide`. يُمرَّر `passageId` مفتاحًا (`key`) للمشغل، فيعيد تغيّر المقطع تركيبه.
- لا تُستخدم مؤقتات. تعيش القائمة في ذاكرة المكوّن فقط: لا تنزيل، ولا Service Worker أو IndexedDB أو تخزين outbox، ولا ذاكرة تخزين مؤقت للتطبيق (لا يضبط التصميم التخزين المؤقت الاعتيادي للوسائط الذي يجريه المتصفح نفسه).
- لا يستورد رمز المشغل عميل API ولا وحدة أحداث الجلسة؛ ويفرض ذلك اختبار (يُسمح باستيراد النوع `PassageView` فقط بصيغة type-only).

### 3.8 ترويسات المضيف (قرار)

- `Referrer-Policy: no-referrer` على كل مسار في مضيف الواجهة، تُضبط في `headers()` داخل `next.config.ts`. ليس لعنصر audio خاصية `referrerpolicy`، فترويسة المضيف هي وسيلة التحكم. حارس: تحت `no-referrer` ترسل المتصفحات `Origin: null` مع الطلب غير GET الذي لا يكون وضعه (mode) "cors" (نموذج POST أصلي، أو fetch بوضع "same-origin")، وهذا يُفشل فحص Origin في API. لذلك يتضمن التنفيذ اختبارًا آليًا يثبت أن طلب POST ينفذه التطبيق عبر عميل API الخاص به يصل إلى الخلفية الوهمية (stub backend) بقيمة Origin الحقيقية والترويسة فعّالة، وأن النماذج تُرسل دائمًا عبر السكربت. إن تعذّر نجاح هذا الاختبار تصبح الترويسة `same-origin` (الخصوصية نفسها تجاه مضيف الصوت) ويُبلَّغ المالك بالتغيير.
- `Content-Security-Policy`: تُضاف الآن بتوجيه واحد فقط، هو `media-src 'self' https://everyayah.com`. ومع غياب `default-src` تبقى السكربتات والأنماط والخطوط والصور بلا تقييد، فلا يحتاج Next.js إلى nonces؛ وتُحمَّل الوسائط من أصل التطبيق ومن everyayah.com فقط، وهذا يمنع أيضًا تحويلات الوسائط إلى مضيفات أخرى. سياسة CSP أوسع تحصين لاحق خارج هذه الميزة.
- لا خاصية `crossorigin` على عنصر audio: لا يقرأ التطبيق بيانات الصوت، فلا حاجة إلى وضع CORS (هذا تطبيق لقاعدة §3.2؛ وقد يعيد QAUD-04 النظر بعد التحقق من CORS لجميع الملفات).
- تفحص الاختبارات الترويستين على التطبيق المبني.

### 3.9 واجهة مشغل خطوة التعلم في S-19 (Approved: D82؛ ليست جزءًا من اعتماد D78 لبوابة G1؛ التنفيذ مؤجل بقرار D82)

- الموضع: في خطوة التعلم من S-19 لمقطع قرآني فقط، تحت كتلة النص الأصلي وسطر مصدرها (c8 وc9) وفوق مفتاح الإخفاء (c12). لا يظهر أبدًا في خطوات الأسئلة (المراجعة والتدريب والاختبار)، ولا في الألعاب S-14 إلى S-18، ولا في الاختبار الأولي S-09، ولا لأي مقطع حديثي. لا يؤثر مفتاح الإخفاء في المشغل. «ابدأ التدريب» يغادر خطوة التعلم، فيُحرَّر المشغل.
- البنية: مجموعة اسمها «تلاوة المقطع» / "Passage recitation" (`role="group"` بهذا الاسم المتاح، accessible name)؛ بلا تعبئة بطاقة؛ أزرار ثانوية ونصية فقط، فلا تنافس الإجراء الأساسي اللاصق.
- قبل أول تشغيل، سطرا تنبيه (نمط التنبيه في UI-tokens §6.12، `--q-text-small`، `--q-color-text-secondary`): «الصوت يُشغّل من مصدر خارجي ويحتاج الإنترنت» / "The audio plays from an external source and needs the internet."؛ «التلاوة للآية كاملة.» / "The recitation covers the whole ayah."
- عناصر التحكم والتسميات:

| عنصر التحكم | العربية | English | ملاحظات |
|---|---|---|---|
| تشغيل وإيقاف مؤقت ومتابعة (زر واحد يتغير اسمه في مكانه) | تشغيل التلاوة · إيقاف مؤقت للتلاوة · متابعة التلاوة | Play recitation · Pause recitation · Resume recitation | زر ثانوي، 48 px؛ يحتفظ بالتركيز عند تغيّر تسميته |
| إيقاف | إيقاف التلاوة | Stop recitation | زر نصي، 44 px؛ يظهر بعد أول تشغيل؛ يحرّر `src` ويعود إلى حالة idle |
| مربع تكرار (منفصل عن الأزرار) | تكرار المقطع | Repeat the passage | غير محدد افتراضيًا؛ وعند تحديده تعود القائمة إلى الآية الأولى بعد انتهاء الأخيرة، حتى يوقف المتعلم التشغيل مؤقتًا أو يوقفه أو يغادر الخطوة |
| سطر الحالة (`role="status"`، polite) | تُتلى الآية {k} من {n} ({reference}) · التلاوة متوقفة مؤقتًا عند الآية {k} من {n} · انتهت التلاوة. · جارٍ تحميل التلاوة… | Playing ayah {k} of {n} ({reference}) · Paused at ayah {k} of {n} · The recitation has ended. · Loading the recitation… | يُعلن عند تغيّر الحالة فقط، لا كل ثانية؛ {reference} داخل عنصر `bdi`؛ الأرقام مهيأة كما في بقية الواجهة (UI-tokens §3.4) |

- الحالات: idle وloading وplaying وpaused وended وerror وoffline وunavailable (نصوصها في §3.6 وفي الجدول أعلاه). لا يُسند `src` إلا داخل معالج نقرة التشغيل؛ وعنصر audio فيه `preload="none"` وبلا خاصية `controls` وبلا `src` قبل تلك النقرة؛ ويقود الحدث `ended` إلى الآية التالية في العنصر نفسه (لا عنصر جديد لكل آية).
- لوحة المفاتيح وقارئ الشاشة: عنصرا button وcheckbox أصليان؛ ترتيب Tab: التشغيل أو الإيقاف المؤقت، ثم الإيقاف، ثم التكرار؛ يفعّل Space وEnter العنصر؛ لا اختصارات عامة (يبقى Esc لورقة الإيقاف المؤقت في S-19)؛ لا ينقل التشغيل التركيز أبدًا. الحركة المخفضة ومؤشرات قراءة التصميم (Design Read) في D80 (ENERGY 1 / RHYTHM 1 / MOTION 1): لا حركة إطلاقًا (لا شكل موجي ولا شريط متحرك، ونص تحميل ثابت). الأهداف: أزرار 48 px، وصف مربع التحديد 44 px؛ خصائص CSS المنطقية لاتجاهي RTL وLTR. يحتفظ المشغل بتسميات نصية فقط؛ لا تُستخدم فيه مجموعة أيقونات Lucide التي اختارها D81.
- نسبة القارئ والمصدر (مثل اسم القارئ) تنتظر سجل الحقوق والشروط في QAUD-04؛ ولا تُكتب الآن.

## 4. الخصوصية والاستضافة والموافقات

تبقى طلبات API والجلسة وملفات تعريف الارتباط والمصادقة على أصل Vercel الحالي، حيث يمرر Next.js طلبات /api/* إلى FastAPI على Render كما تصفه المعمارية القائمة. طلب الوسائط HTTPS المباشر إلى EveryAyah هو استثناء مقترح ومحدود لهذا الملحق، ضمن نطاق الميزة الذي وافق عليه المالك؛ لا يمر عبر FastAPI ولا يوسع CORS أو أصل المصادقة للتطبيق. يحمل المتصفح الصوت مباشرة من المصدر؛ يرى المصدر عنوان IP وبيانات المتصفح المعتادة. يجب ألا يرسل التطبيق ترويسة مصادقة أو معرّف حساب أو جلسة أو خطة أو هدف متعلم إلى نطاق الصوت.

نص واجهة مقترح بالعربية: «الصوت يُشغّل من مصدر خارجي ويحتاج الإنترنت». تضاف ترجمة إنجليزية مقابلة. تُراجع صياغة الخصوصية الحالية في الشاشتين S-03 وS-26 ضمن مراجعة G1. وتُراجع سياسة Referrer-Policy: no-referrer على مستوى المضيف؛ لا يُفترض وجود خاصية عنصر HTML خاصة لذلك. إذا كانت سياسة CSP موجودة، يضاف نطاق everyayah.com إلى media-src وحده، دون توسيع بقية المصادر.

تشغيل عينة عبر MCP أو نجاح رابط مباشر لا يمنح حق إعادة النشر. قبل الإتاحة العامة يلزم تسجيل شروط المصدر وحقوق الاستخدام، والتحقق من تغطية المراجع الـ564 وإتاحة الملفات واتساقها الحرفي ومطابقة القارئ والرواية. يلزم G5 قبل أي نشر/إعداد خدمة، وG6 قبل استخدام المحتوى علنًا؛ التصميم الحالي لا يمنحهما.

## 6. معايير القبول والتحقق

### فحوص مستقبلية مطلوبة

- ربط مراجع surah:ayah الموثوقة بدقة، بما في ذلك وحدة ليست رقمها التسلسلي صفرًا؛ ورفض المراجع المكررة أو غير الصالحة أو غير القرآنية أو خارج 78–114 بلا تخمين.
- تعطيل المقطع عند غياب أي إدخال في الفهرس أو تعذر الملف، مع بقاء النص والجلسة قابلين للاستخدام.
- التحقق الشبكي من جميع الملفات المستخدمة: HTTPS، ونوع audio/mpeg، وطلبات النطاقات، وCORS، والتغطية والملاءمة للصوت؛ لا تكفي عينات طرفية لإثبات التغطية.
- فحص نقرة التشغيل والإيقاف والتتابع والتكرار واستعادة الخطأ والتنقل والتنظيف على Safari iOS وChrome Android ضمن مصفوفة D67، وبالعربية RTL والإنجليزية LTR ولوحة المفاتيح وقارئ الشاشة.
- إثبات عدم إسناد src قبل فعل تشغيل صريح، وإظهار رفض play() بلا إعادة محاولة آلية؛ واختبار أن أحداث ended/play القديمة لا تعيد تشغيل الوسائط بعد الانتقال أو تنظيف الجلسة/الحساب/التبويب.
- إثبات إيقاف الصوت قبل الأسئلة والمراحل المقيمة، وعدم إرسال حدث تقدم أو إجابة أو وقت نشاط من تشغيل الوسائط، وعدم تسرب مساعدة إلى المراجعة/الاختبار.
- مراجعة ترويسات الطلب والخصوصية وCSP وسياسة المرجع؛ واختبار حالة عدم الشبكة/الصوت وعدم وجود تخزين صوت محلي أو تنزيل.
- تأكيد أن النص الأصلي وDTOs وقاعدة البيانات لا تتغير، وأن المحتوى يظل ظاهرًا والتعلم مستمرًا مع فشل الصوت.
- اختبارات QAUD-03a المخططة:
  - ربط القائمة وكل قاعدة من §3.5.
  - التحقق من الرابط بالمساواة التامة.
  - غياب `src` حتى نقرة التشغيل، مع `preload="none"`.
  - التحرير عند إزالة المكوّن وتغيّر المقطع و`visibilitychange` و`pagehide`.
  - تجاهل أحداث `ended` و`play` القديمة بعد التحرير.
  - لوحة المفاتيح والأسماء المتاحة (accessible names).
  - حالات عدم الاتصال ورفض التشغيل التلقائي وخطأ الوسائط.
  - عدم استيراد API.
  - وجود `Referrer-Policy` وCSP على التطبيق المبني، واختبار حارس Origin في §3.8.
  - اعتراض كل الشبكة.
  - فهرس اختباري (test-only manifest fixture) يحتوي المرجعين المتحقق منهما في §6 وحدهما (`78:1` و`114:6`) بنمط الرابط الموثق.

### ما تحقق حاليًا وحدوده

في 4 أكتوبر 2026، أعاد مصدر MCP عينة https://everyayah.com/data/Husary_64kbps/078001.mp3 للآية المرجعية 78:1 مع صفحة QuranEnc المرجعية https://islamenc.com/ar/quran/78/1؛ استجاب HEAD بـ200 وaudio/mpeg وطول 64782 بايت، وأفادت العينة بدعم النطاق وCORS. كما أعادت عينة https://everyayah.com/data/Husary_64kbps/114006.mp3 استجابة نطاق GET 206 للبايتات 0–4095 من 68753 بايت، وبداية إطار MP3، للمرجع 114:6.
