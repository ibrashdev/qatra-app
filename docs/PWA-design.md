# قطرة غيث — تصميم التثبيت والخطة المحملة دون اتصال

الإصدار ١٣ · ٤ أكتوبر ٢٠٢٦. يصف هذا المستند التثبيت والعمل بالخطة المحملة وفق D55–D69، بما في ذلك AI مجاني فقط وأحكام الإتقان واليوم والطابور والخصوصية المحلية؛ ويسجل مصفوفة الأجهزة والمتصفحات (D67)، وحسم مدخلات الإتقان (D66)، وقبول المالك حقوق التنزيل المحلي بانتظار شروط الناشر (D68). إعداد التصميم متوافق مع D63 ولا يتجاوز بوابات الاعتماد؛ التفاصيل التقنية Needs Review حيث يذكر. جميع مسارات التطبيق Planned. المتابعة في Readiness.tracker.md. القسم ٥ (وما يحيل إليه في §٤) مواءم مع API-spec.md الإصدار ١.١ والعقد Implementation-contract.md الإصدار ١.٣ بتاريخ ٤ أكتوبر ٢٠٢٦ (Needs Review): تسميات SessionEvent و OfflineEnvelope و EventsResponse، وإتمام الجلسة دون جسم، ورموز 409/422؛ وتنتظر هذه الأقسام المعدلة اعتماد المالك عند البوابة G0، ولا يتغير وضع اعتماد ما سبق اعتماده.

## ١. النطاق والواقع المتحقق منه

المطلوب تثبيت التطبيق على الجهاز، ثم إعادة فتحه من إغلاق كامل دون إنترنت لتعلم دروس الخطة النشطة وألعابها التي اكتمل تنزيلها سابقًا. التسجيل والدخول واسترجاع الحساب وإنشاء/تعديل خطة وتنزيل مادة جديدة والتحقق الخادمي والمزامنة تحتاج إنترنت. لا وعد بأول زيارة دون إنترنت، أو بتوفر كل الكتاب تلقائيًا، أو بتثبيت متطابق في جميع المتصفحات. تثبيت الأيقونة وحده لا يثبت جاهزية الخطة للعمل دون اتصال.

وجهتا التطبيق وفق D61 هما qatra-app/frontend وqatra-app/backend؛ جميع المسارات أدناه Planned. لا يشهد وجود تصميم PWA أو مواصفاته بتشغيل التطبيق أو خدماته.

يستخدم التصميم المقترح manifest و Service Worker مقيدًا وغلافًا ثابتًا؛ يتحدد توافق التنفيذ وفق إصدار Next.js المعتمد عند الإعداد. المرجع: [دليل Next.js الرسمي](https://nextjs.org/docs/app/guides/progressive-web-apps). لا إشعارات Push أو مزامنة خلفية إلزامية ضمن D46، ولا يفترض نجاح إعادة الفتح دون اتصال حتى فحص build فعلي لاحق.

## ٣. غلاف بدء كامل وموارد الألعاب

يجب أن ينتج build غلاف /offline عامًا و HTML و JS و CSS وكل التبعيات اللازمة للعرض والمحركات الأربعة: الخطوط المحلية والقاموس العربي/الإنجليزي والأيقونات والصور اللازمة وأي lazy chunks. القائمة allowlist مشتقة من ناتج build وإغلاق التبعيات الفعلي، بما فيه imports الديناميكية؛ wildcard لكل /_next أو حفظ الموارد التي زارها المستخدم سابقًا لا يضمن لعبة لم يفتحها بعد. يثبت الغلاف عدم الحاجة إلى RSC أو خادم عند الإقلاع البارد قبل اعتماده. Next prerendering وحده لا يعد إثباتًا لهذا السلوك.

install للعامل يجهز cache مؤقتًا باسم buildId ثم يعلن shellReady فقط بعد نجاح جميع موارد الغلاف؛ أي مورد ناقص يبقي الإصدار السابق صالحًا ولا يجعل التنزيل جاهزًا. تسجيل العامل ونجاح manifest لا يكفيان: يتحقق العميل من العامل المتحكم ومن الغلاف ومن موارد اللعبة والخطة، ويعرض «الخطة جاهزة دون اتصال» بعد تحققها كلها. تنشأ الموارد من الإنتاج، لا من chunks خادم التطوير. موارد المحتوى الديني تحفظ في IndexedDB بنطاق الحساب، لا مع cache الغلاف العام.

| نوع الطلب | سياسة العامل المقترحة |
|---|---|
| موارد build العامة في allowlist | cache-first للإصدار المتحكم، تحميل الموارد المطابقة للبصمة/النسخة فقط؛ لا اعتماد شبكة أثناء تشغيل خطة جاهزة |
| document على /offline | غلاف عام ثابت متوافق مع build المتحكم؛ حالة الحساب تأتي من IndexedDB بعد بدء العميل |
| تنقل GET إلى واجهة المتعلم عند تعذر الشبكة | تحويل إلى /offline دون نقل query شخصية؛ لا حفظ HTML الصفحة الشخصية أو إرجاعه من cache |
| /api/* والمصادقة وطلبات غير GET و Server Actions | network-only؛ لا generic cache ولا replay بالعامل؛ outbox التطبيق وحده يعيد أحداث التعلم الموافق عليها |
| RSC/Flight و SSR شخصي و HTML تسجيل/استرجاع/إدارة وأصول خارج allowlist | لا تخزين بالعامل؛ لا مسح ترويسات RSC لاعتباره HTML عامًا؛ الدخول/الإدارة خارج غلاف الأوفلاين |

start_url=/offline يجعل بداية التطبيق مثبتة وقابلة للتحميل من cache دون نجاح JWT أو رد خادم. عند وجود إنترنت يطلب الغلاف /api/me قبل استخدام بيانات الحساب أو المزامنة؛ عند انقطاعه يفتح النسخة المحلية المسموح بها فقط مع بيان «غير متصل — النتائج بانتظار التحقق». غياب الخطة/الغلاف أو عدم اكتمالهما يعرض طلب الاتصال والتنزيل؛ لا شاشة تحاكي إنجازًا محفوظًا.

حالة إيقاظ الخادم المجاني (D48 ج): FastAPI على خدمة Render المجانية تتوقف بعد ١٥ دقيقة بلا طلبات وتستيقظ في نحو دقيقة. الواجهة على Vercel والغلاف /offline يظهران فورًا؛ عند الفتح مع وجود شبكة يستدعي العميل GET /api/health بطلبات قصيرة متكررة مع تراجع (backoff)، لا طلبًا واحدًا طويلًا، ويعرض «جارٍ تشغيل الخادم المجاني، قد يستغرق ذلك دقيقة.» حتى يرد الخادم، ثم يطلب /api/me ويكمل revalidate والمزامنة (§٦). الإيقاظ حالة اتصال لا حالة صلاحية: مهلة الإيقاظ أو فشله لا يجعلان اللقطة stale أو revoked أو expired، ولا يمسحان outbox أو يطلبان دخولًا جديدًا؛ تبقى الخطة المحملة قابلة للعمل دون اتصال وفق D46 مع بيان «غير متصل — النتائج بانتظار التحقق»، وتعاد المحاولة لاحقًا أو بزر «إعادة المحاولة». فترات التراجع وعدد المحاولات وحد الانتظار قيم تنفيذ Needs Review. خطر غير متحقق: قد تقطع مهلة إعادة التوجيه (rewrites) في Vercel طلبًا ينتظر استيقاظ Render؛ لذلك الطلبات قصيرة، ويتحقق أثناء البناء من سلوك المهلة قبل الاعتماد عليه.

## ٤. لقطة الخطة و IndexedDB

PlanSnapshot مقترح: snapshotId، schemaVersion، protocolVersion، userId (معرف ملكية غير سري)، planId، planVersion، editionId، bankVersion، targetScope، downloadedTargetRefs، learningTimeZone، dailyGoalMs، contentHashes، verifiedAt، contentValidity، normalizationPolicyVersion، scoringPolicyVersion، preparedSessions، lessons، games، references. النصوص أصول النسخة مع صفحاتها (وللنسخ الويب الرابط الأصلي canonical URL مرجعًا بجانب النص، D68) والطبعة والهوامش؛ games مراجع/قوالب مقيدة ومعيار تطبيع/تقييم صادر من الخادم بإصدارات معلنة، ولا محتوى مولد. evaluateProvisionalAnswer في lib/games/evaluation.ts يستخدم هذا المعيار لرد مؤقت؛ الخادم يعيد التصحيح من النسخة/السياسة المثبتتين، ولا يعتمد نتيجة الدالة المحلية. contentValidity هو سجل صلاحية/حقوق آخر فحص خادمي، وليس تفويضًا أبديًا أو مدة أوفلاين جديدة معتمدة.

كل preparedSessions يتضمن sessionId خادميًا مملوكًا، kind=daily/game، لقطة الخطة/البنك، أهداف وأسئلة ومعايير تطبيع معلنة ومراجع أصلية؛ الأربعة قوالب وجميع خياراتها/مشتتاتها اللازمة متاحة دون API. وفق D64 تقبل لعبة `word_choice` خيار كلمة أو جزءًا متصلًا من المصدر؛ تمثيل نطاق الجزء وخيارات متعددة الكلمات وربط دليل التغطية بالجزء المختبر محدد في [Implementation-contract.md](Implementation-contract.md) §2.4 و§7، ولا يفرض هذا العقد `target_word_index` أو جواب كلمة واحدة للاختيار أو حقولًا معتمدة جديدة. لا يحتسب النص المعروض في السياق دون اختبار دليل تغطية. جواب AnswerPayload المحلي والمعيار المحلي يسمحان بتغذية راجعة مؤقتة؛ لا يلغي ذلك إعادة تصحيح الخادم. لا تنشأ جلسة خادمية وهمية محليًا. المقترح التقني هو إعادة استعمال descriptor الجلسة المعدة للهدف/اللعبة في تشغيلات محلية متعددة، مع clientRunId جديد و clientEventId فريد لكل حدث، ودون إغلاق الجلسة الخادمية بينما الجهاز غير متصل. اكتمال لعبة محلية لا يستهلك descriptor مرة واحدة؛ الإغلاق الخادمي يأتي بعد replay لكل تشغيلاتها وإقرارها. هذا العقد وحقول إعادة الاستعمال/الحفظ تحتاج مراجعة قبل التنفيذ، ولا تفرض عدد محاولات أو TTL جديدًا.

إذا لم تكن جلسة الهدف/القالب معدة ومحملة، أو أغلقت/حجبت عند إعادة التحقق، أو لم يدعم العقد النهائي إعادة استعمالها، فلا يولد العميل معرف خادم بديلًا ولا يستنفد مخزونًا محدودًا بصمت: يعرض «هذه اللعبة تحتاج اتصالًا لتجهيزها مجددًا» مع حفظ بقية الخطة و outbox. اعتماد بديل يقوم على عدد جلسات محجوزة يفتح سؤال الاستنفاد قبل التنفيذ؛ لا يخترع هذا التصميم قدرة عددية أو مدة أوفلاين. حدود التخزين/الفشل تبقى معلنة حتى مع descriptor قابل للتكرار.

| المخزن المقترح | الحدود |
|---|---|
| ownerState | صاحب النسخة المحلية الحالي، localGeneration، حالة logoutPending؛ ليس JWT أو سر مصادقة |
| planSnapshots / contentCache | مفاتيح مركبة userId/planId/editionId/bankVersion؛ النسخ غير المنشورة/المعروفة بالسحب غير صالحة للعرض |
| activeRuns | حالة اللعبة/الجلسة المحلية ومراجع اللقطة، مع الحفظ قبل إغلاق الصفحة |
| pendingEvents | ملكية ثابتة و clientEventId و clientRunId ومعرف الجلسة (يحدد مسار الطلب فقط ولا يرسل حقلًا في SessionEvent)، النسخة والمراجع والإجابة العابرة عند لزومها وفترات النشاط؛ لا نص ملاحظة D45 أو هدف حر أو كلمة مرور |
| syncState | إقرارات الخادم (دون cursor في العقد)، حالة الأحداث ومعلومات التعارض، بلا Auth tokens |

التنزيل يجري إلى staging بعلامة incomplete؛ يطابق النطاق والبصمات والمراجع والأصول والموارد، ثم يثبت snapshot جاهزًا في معاملة IndexedDB. جاهزية التطبيق تجمع shellReady مع snapshotReady ولا تفترض معاملة ذرية بين Cache Storage و IndexedDB؛ يجري فحصهما عند كل إقلاع. تحديث خطة محملة لا يستبدل جلسة جارية أو يحذف outbox القديم؛ النسخ المتعارضة توقف مزامنتها حتى القرار الصحيح.

عقود وحدات TypeScript المقترحة، ليست exports منفذة:

- types.ts: PlanSnapshot؛ CacheResult={ready،snapshotId،failureCode?}؛ SyncResult={acknowledgedIds،pendingIds،blockedIds،reasonCode?}؛ SessionEvent و OfflineEnvelope (أسماء العقد، §٥) حدث التعلم وغلاف إعادة تشغيله، و PendingEvent صف الطابور الذي يضم ownerId و state و SessionEvent مع OfflineEnvelope دون تغيير هوية حدثه عند إعادة المحاولة؛ ليست تسميتين متنافستين للمعرف نفسه.
- plan-cache.ts: cacheActivePlan(snapshot):Promise<CacheResult>؛ readReadyPlan(ownerId):Promise<PlanSnapshot|null>؛ يعيد null عند عدم اكتمال/توافق/ملكية النسخة.
- outbox.ts: enqueueEvent(ownerId,event):Promise<void>؛ حفظ ذري وفريد للمعرف، لا نجاح محلي دائم قبل نجاح الكتابة.
- sync.ts: syncForeground(ownerId):Promise<SyncResult>؛ لا تغير ownerId بعد enqueue ولا ترفع الحدث تحت حساب آخر.
- db.ts: clearAccountCache(ownerId):Promise<void>؛ يزيل جميع البيانات الشخصية ويحدث generation؛ الفشل يمنع فتح حساب آخر حتى إتمام المسح.
- pwa/register.ts: registerServiceWorker()؛ pwa/update.ts: inspectUpdate(registration) و applyUpdateWhenSafe(registration)؛ تغيير العامل يحتاج تنسيق تبويبات/حفظ الجلسة وتوافق schema، لا تحديث قسري أثناء اللعب.

## ٥. عقود REST المقترحة للتنزيل والمزامنة

مواءم مع API-spec.md الإصدار ١.١ بتاريخ ٤ أكتوبر ٢٠٢٦ (اعتمده المالك بقرار D74 في ٤ أكتوبر ٢٠٢٦؛ تنفيذ العمل دون اتصال مؤجل في الخيار B، D74): أسماء الأحداث والاستجابات هي أسماء Implementation-contract.md §7 (SessionEvent و OfflineEnvelope و EventsResponse)، وإتمام الجلسة دون جسم، وخطأ اللقطات القديمة 409 version_conflict.

كلها عبر Cookie __Host-qatra_session و Origin والتحقق الخادمي الحالي؛ استجابات الحساب/اللقطات Cache-Control: no-store ولا يحفظها CDN أو العامل. توقعات الطلب DTO، والحجم والتقسيم/الحدود العددية Needs Review، لا أسماء endpoints منفذة الآن.

| العملية | الطلب والاستجابة والتحقق |
|---|---|
| POST /api/plans/:id/offline-snapshots | clientOperationId UUID، expectedPlanVersion integer، downloadTargetRefs قائمة مراجع؛ ينشئ لقطة وجلسات معدة خادميًا بعد التحقق من الحساب والخطة النشطة والنطاق والنسخة والحقوق. 201: PlanSnapshot؛ إعادة العملية بالمدخل نفسه 200 لنفس اللقطة، واختلافه 409. لا جلسات جديدة بأثر جانبي لـ GET |
| GET /api/offline-snapshots/:snapshotId | استرجاع/استكمال لقطة مملوكة، 200 مع DTO أو manifest تحميل مجزأ بمواضع وبصمات؛ لا نشر عام للنص أو بيانات حساب آخر؛ جاهزية الأجزاء كلها شرط التشغيل |
| POST /api/offline/revalidate | snapshotId، expectedPlanVersion، editionId، bankVersion؛ الخادم يراجع الملكية والخطة والنسخة/البنك والجلسات والصلاحية الحالية. 200: status=available/stale/revoked/expired، currentPlanVersion، allowedSessionRefs، catalogVersion، reasonCode. expired لصلاحية انتهت فعلًا وفق بيانات المصدر/الجلسة، لا TTL مخترع؛ available يجيز التشغيل الجديد، أما replay القديم فيحتاج قرار أهلية لكل حدث وفق D59 ولو تغيرت اللقطة |
| POST /api/sessions/:id/events | الجسم {events: SessionEvent[]} (حتى ١٠٠)، ومعرف الجلسة في المسار؛ يحمل كل حدث أُنشئ دون اتصال OfflineEnvelope أدناه؛ يصحح الخادم الإجابة ويطابق الجلسة/النطاق ويمنع التكرار والتداخل. 200: EventsResponse = acknowledged (معرفات) و duplicate (أُقر معرفها سابقًا) و pending (عناصر {clientEventId, reasonCode}) و rejected (عناصر {clientEventId, code}) و results (AnswerResult[]) و daily؛ لا cursor؛ الإقرار فقط يزيل الحدث من outbox |
| POST /api/sessions/:id/complete | دون جسم؛ يقبل ترويسة Idempotency-Key (UUID) اختيارية فقط لإعادة الإرسال الآمنة؛ يرسل بعد إقرار أحداث التشغيل اللازمة؛ يغلق وفق العقد (CompleteResponse)، ولا يصنع إتمام اليوم أو زمنًا ثانيًا من مجرد الإغلاق |

SessionEvent داخل OfflineEnvelope (أسماء العقد، C-05): معرف الجلسة في مسار الطلب لا في الحدث؛ type=answer أو activity؛ answer يحمل clientEventId، questionId، answer (AnswerPayload: {order: TokenRef[]} أو {optionId} أو {text})، hintUsed، occurredAt، durationMs؛ activity يحمل clientEventId، startedAt، endedAt، activeMs. يضاف إلى كل حدث أُنشئ دون اتصال (كل الحقول أو لا شيء) OfflineEnvelope: clientRunId UUID، snapshotId، protocolVersion=1، planVersion، editionId، bankVersion، normalizationPolicyVersion، scoringPolicyVersion، localSequence. أسقطت الأسماء السابقة eventKind و sessionId و targetRefs و answerRef و orderedTokenRefs (الأهداف تستنتج من questionId والجواب في AnswerPayload). correct و dailyPercent و confirmedAt المحلية ليست حقائق يعتمدها الخادم. ترتيب المحاولات عبر أجهزة/تبويبات ومعالجة ساعة معدلة Needs Review؛ لا يتحول localSequence وحده إلى إثبات زمن موثوق.

401 يوقف replay ويطلب دخولًا متصلًا؛ 404 لا يكشف ملكية حساب آخر؛ 409 version_conflict عند expectedPlanVersion قديم (C-11، توضيح مقترح لعقد v1.4 لأن §7 يذكر 422 فقط) أو إعادة معرف بمدخل مختلف؛ 422 validation_error لقيم مشوهة أو مرجع مجهول أو نسخة/نطاق غير صالح؛ 429/503 تعيد محاولة محدودة مع backoff؛ رد 5xx أو انتهاء المهلة أثناء استيقاظ الخادم المجاني يعامل كحالة إيقاظ/اتصال (§٣، D48) لا كرفض أو تعارض، ولا يغير حالة اللقطة أو الأحداث؛ limits/دفعات/حدود الوقت العددية بحاجة للمراجعة. انقطاع الرد يعيد المعرف نفسه؛ لا يولد معرفًا جديدًا ولا يحذف الحدث بلا إقرار. تعذر التحقق لا يعني تسجيل الدخول مجددًا تحت صاحب آخر.

## ٦. إعادة الاتصال وحدود الإنجاز

المزامنة **foreground** عند فتح التطبيق أو عودة اتصال فعلي أو زر «إعادة المحاولة». navigator.onLine إشارة فقط؛ النجاح يثبت بطلب التطبيق. بعد اكتمال إيقاظ الخادم عبر GET /api/health (§٣، D48)، ثم /api/me ومطابقة المالك، يعمل revalidate، ثم replay بتسلسل ثابت، ثم جلب التقدم المعتمد وتحديث اللقطة. قفل/معاملة IndexedDB و localGeneration يمنعان عمال مزامنة متعددة؛ إقرارات الخادم/idempotency تبقي الأثر واحدًا إذا تكرر الطلب رغم القفل. لا يعتمد MVP على Background Sync؛ دعمها محدود بحسب [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Background_Synchronization_API)، ولا وعد بمزامنة والتطبيق مغلق.

stale يوقف العرض/التشغيل الجديد المتأثر حتى إعادة التحقق؛ revoked/expired يمنع عرض النص المعروف بالحظر ويمسح مادته محليًا. أهلية الحدث القديم منفصلة عن إتاحة اللقطة الحالية: D59 يبقي الدليل السابق القابل للتحقق في الخطة الأصلية وإصدارها فقط، ولا ينقله إلى خطة/نسخة جديدة. تعذر إثبات أنه سبق التغيير/السحب يبقيه pending بلا إنجاز، ولا يجعل وقت الجهاز دليلًا. لا إرسال لنص المصدر المحظور، ولا حذف للطابور لحل التعارض. العقد المقترح يرد على كل حدث بأهليته/reasonCode؛ تفاصيل معيار الإثبات والترتيب عبر الأجهزة Needs Review.

الإنجاز المحلي مؤقت: D40 وقت نشط بلا توقف/خلفية/placement أو تكرار/تداخل؛ اليوم حتى١٠٠٪ والزيادة بلا ترحيل. ≥٣ صحيح متوالٍ دليل أولي وفق D41. تتطلب سياسة D64 تغطية الأجزاء المستهدفة للمقطع كاملًا تراكميًا عبر التدريب والمراجعات، ونجاح مراجعات أيام ١/٣/٧؛ لا يلزم اختبار كل كلمة أو كل الألعاب في جولة واحدة. تدوير المواضع والألعاب، وترتيب أجزاء أكبر، والأسئلة المفتاحية/الاستكمال تقلل الملل والتكرار مع بقاء النص الكامل ثابتًا. لا يعد عرض النص وحده دليل تغطية. `word_choice` يقبل كلمة أو جزءًا متصلًا من المصدر. حسم D66 (تعديل صريح لـ D64 اعتمده المالك في ٤ أكتوبر ٢٠٢٦) تمثيل السؤال/الأجزاء وأدلة التغطية وحجم الجولات وهوية تجميع الأهداف ومقام/وزن الإنجاز العام وأثر الإخفاق اللاحق ([Implementation-contract.md](Implementation-contract.md) §4): المقطع هدف الحفظ وله أجزاء تغطية، والإنجاز العام = floor(١٠٠ × كلمات المقاطع المؤكدة ÷ كلمات نطاق الخطة النشطة للمسارات المختارة)، وإخفاق المراجعة قبل التأكيد يعيد السلسلة إلى المرحلة ١ وبعده يجعل المقطع «يحتاج تحديثًا». يعدل D66 بند D64 «لا رقم ثابتًا جديدًا ولا نسبة نجاح عددية» لهذه القواعد وحدها؛ لا ادعاء حفظ حرفي كامل. D57 يبدأ تعديل الوقت اليومي والمنطقة الزمنية يوم التعلم التالي بلا أثر رجعي أو إتمام مكرر، مع تثبيت تاريخ الخطة واليوم؛ تفاصيل انتقال التاريخ/الدليل Needs Review. D42 يسمح بمادة يوم لاحق داخل الخطة المحملة دون قفل تاريخي.

## ٧. الخصوصية والخروج وتعدد التبويبات

النسخة المحلية السابقة تفتح لأصحاب الجهاز بعد استعمال الحساب سابقًا دون تحقق خادمي جديد؛ **هذا وصول محلي مؤقت، وليس تسجيل دخول أو إثبات صلاحية جلسة خادم**. لا يمكن قراءة HttpOnly Cookie للتحقق من انتهائها دون شبكة. جهاز مشترك يستطيع عرض النسخة الباقية؛ يظهر هذا الحد عند التنزيل مع خيار مسحها. لا تشفير شكلي بمفتاح بجانب البيانات، ولا ادعاء أن userId في IndexedDB يمنع صاحب الجهاز أو XSS. التشفير المحلي بقفل مستقل سياسة مستقبلية تحتاج قرارًا، وليست جزءًا مفترضًا من D46.

الخروج أو تبديل الحساب يغلق الجلسات المحلية ويبطل generation ويمسح مخازن الحساب والنصوص والأجوبة المعلقة في جميع التبويبات قبل عرض أي حساب آخر؛ BroadcastChannel/حدث وسيط يسرع الإخطار، ومعاملة ownerState وفحص generation قبل كل قراءة/كتابة يمنعان اعتماد الرسالة وحدها. لا أسماء حساب في cache الغلاف أو URL. إذا فشل المسح يبقى العرض الشخصي مقفلًا ويطلب إصلاح التخزين، ولا يكتفي بتنبيه ثم يفتح حسابًا آخر.

خروج بلا شبكة يمسح النسخة ويوقف عرضها فورًا ويسجل logoutPending كعلم منع محلي، دون سر أو بيانات التعلم؛ Cookie HttpOnly لا يستطيع العميل محوها. عند عودة الشبكة /api/auth/logout أولًا قبل إعادة استعمال الحساب القديم، ثم يعاد الدخول عند الحاجة. هذا ليس إلغاءً خادميًا ناجحًا بينما الجهاز مغلق. حذف الحساب النهائي يحتاج اتصالًا وكلمة المرور/التأكيد الحاليين؛ لا يعرض نجاح الحذف عند انقطاع الشبكة. يمكن مسح النسخة المحلية مستقلًا مع بيان أنه لا يحذف الحساب.

D58 يقبل تأخر أثر تغيير كلمة المرور/حذف الحساب/خروج بعيد/سحب النسخة حتى عودة اتصال الجهاز المغلق أو غير المتصل، ويقبل وصول حامل الجهاز إلى المحلي الباقي دون قفل أو انتهاء جديد. بعد الاتصال والتحقق يوقف 401 الوصول/المزامنة، ويوقف اكتشاف السحب عرض النص ويمسحه. الخروج الجاري يمسح المحلي فورًا؛ لا وعد مسح بعيد لحظي. هذه سياسة معتمدة، لا سؤال قبول مفتوح؛ التنفيذ ما زال غير متحقق. التفاصيل في Authentication-and-privacy.md.

## ٨. تحديث البرنامج والتخزين والفشل

العامل الجديد ينتظر؛ لا skipWaiting أو clients.claim قسري أثناء جلسة أو كتابة outbox. يدعم update.ts حفظ التشغيل والتنسيق مع جميع التبويبات، ثم تبديلًا عند حد آمن أو بعد إغلاقها. cache باسم buildId يمنع خلط HTML/JS/CSS من إصدارين. لا ينظف الإصدار القديم قبل غياب مستخدميه وتوافق/نقل البيانات؛ هذه قاعدة تصميم تستند إلى دورة العامل في [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers). لا حذف pendingEvents لتسهيل تحديث.

schemaVersion و protocolVersion لكل لقطة/حدث؛ نقل IndexedDB ذري وغير متلف، ومواجهة versionchange تغلق الاتصالات القديمة. إذا تعذر النقل أو كان التطبيق أقدم من schema الحالية، يتوقف فتح الخطة/الكتابة مع رسالة اتصال/تحديث، ويحفظ outbox؛ التوافق الأمامي والخلفي ومتى يحذف cache القديم شروط إصدار للمراجعة. manifest العام لا يشير إلى بيانات الإصدار الشخصية.

navigator.storage.estimate فحص تقديري، و persist طلب تحسين متانة حيث يتاح، لا ضمان. QuotaExceededError أو فشل transaction يبقي snapshot غير جاهز، ولا يعلن حفظ جواب لم يكتب. إزالة مواد إعادة تنزيلها لا تمس أحداثًا غير مقر بها. لا تعد استمرارية cache أو IDB مضمونة؛ المتصفح قد يطرد بيانات الأصل بحسب [MDN Storage](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria). غياب البيانات عند الإقلاع يعرض حالة تنزيل ناقص/طلب الاتصال، لا حسابًا جديدًا أو إنجازًا صفرًا يكتب فوق الخادم. ما أقره الخادم يستعاد؛ ما فقد قبل الإقرار قد لا يستعاد.

## ٩. قبول التصميم وحدود التوقف

فحوص لاحقة مخططة، **لم تنفذ**: build إنتاج → تنزيل كامل → إغلاق التطبيق والمتصفح → تعطيل الشبكة → فتح الأيقونة/إعادة تحميل /offline → درس وكل لعبة بما فيها chunk لم يفتح سابقًا؛ عدم حصول طلب API/RSC ضروري للعمل؛ غياب التنزيل يعرض حدًا صريحًا. ثم reconnect مع رد ضائع وأحداث مكررة وتبويبين وتداخل زمني؛ لا احتساب مضاعف. تشمل المصفوفة logout offline/online، تبديل حساب ومسح فاشل، 401، سحب/انتهاء المصدر، خطة معدلة، waiting update مع outbox، schema غير متوافقة، طرد cache/IDB والحصة الممتلئة، RTL/LTR والمتصفحات المستهدفة. تحدد مصفوفة الأجهزة والمتصفحات أدناه (D67) نطاق الدعم؛ ولا يدعى تحقق جهاز أو متصفح إلا إن اختبر فعلًا ضمنها.

|---|---|
| المقاسات | هواتف ٣٦٠–٤٣٠ بكسل عموديًا أولًا؛ أجهزة لوحية ٧٦٨–١٠٢٤؛ حاسوب ≥ ١٢٨٠؛ قابل للاستعمال من ٣٢٠ بكسل دون تمرير أفقي |

D45 يبقى مشروطًا.
